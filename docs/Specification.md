# Specification — Tabl

## User Stories & Acceptance Criteria

---

### Epic 1: Управление лекарствами

#### US-01: Добавление лекарства

```
As a пользователь,
I want to добавить лекарство с названием и расписанием,
So that приложение будет напоминать мне о его приёме.

Acceptance Criteria:
Given пользователь открыл экран добавления лекарства
When он вводит название и нажимает "Сохранить"
Then лекарство появляется в списке на главном экране

Given пользователь не ввёл название
When нажимает "Сохранить"
Then показывается ошибка "Введите название лекарства"

Given пользователь указал количество в запасе
When сохраняет лекарство
Then счётчик таблеток отображается на карточке лекарства
```

#### US-02: Редактирование лекарства

```
As a пользователь,
I want to изменить параметры лекарства,
So that актуализировать расписание без удаления истории.

Acceptance Criteria:
Given пользователь открыл редактирование лекарства
When изменяет время приёма и сохраняет
Then все будущие будильники пересчитываются по новому времени
Then история прошлых приёмов сохраняется неизменной
```

#### US-03: Удаление лекарства

```
As a пользователь,
I want to удалить лекарство,
So that убрать его из расписания и списка.

Acceptance Criteria:
Given пользователь нажимает "Удалить" на лекарстве
When появляется диалог подтверждения
Then при "Да" — лекарство и все его будильники удаляются
Then при "Отмена" — ничего не происходит
```

### Epic 2: Расписание приёма

#### US-04: Настройка времени приёма

```
As a пользователь,
I want to задать конкретное время и дни приёма,
So that будильник срабатывал по моему графику.

Acceptance Criteria:
Given пользователь настраивает расписание
When выбирает время 09:00 и дни "пн, ср, пт"
Then будильник срабатывает только в эти дни в 09:00

Given пользователь выбирает "каждый день"
When указывает время 21:00
Then будильник срабатывает ежедневно в 21:00

Given пользователь указывает интервал "каждые 8 часов" от 08:00
Then будильники срабатывают в 08:00, 16:00, 00:00
```

#### US-05: Курс приёма

```
As a пользователь,
I want to задать дату начала и окончания курса,
So that напоминания автоматически прекращались после курса.

Acceptance Criteria:
Given пользователь установил курс с 2026-04-16 по 2026-04-23
When наступает 2026-04-24
Then будильники больше не срабатывают
Then в истории отображается "Курс завершён"
```

### Epic 3: Будильник

#### US-06: Срабатывание push-уведомления

```
As a пользователь,
I want получать уведомление в назначенное время,
So that не пропустить приём лекарства.

Acceptance Criteria:
Given наступило время приёма
When телефон активен или заблокирован
Then появляется heads-up уведомление с именем лекарства, дозой и кнопками

Given уведомление показано
When пользователь не реагирует 30 минут
Then уведомление повторяется (максимум 2 раза)

Given уведомление повторилось 2 раза без ответа
Then приём фиксируется как "пропущен"
Then уведомление убирается из шторки
```

#### US-07: Устойчивость к перезагрузке

```
As a пользователь,
I want чтобы будильники сохранялись после перезагрузки телефона,
So that не потерять расписание при случайной перезагрузке.

Acceptance Criteria:
Given настроены будильники на 3 лекарства
When пользователь перезагружает телефон
Then все будущие будильники восстанавливаются автоматически
Then ни один будильник не пропущен из-за перезагрузки
```

### Epic 4: Подтверждение приёма

#### US-08: Подтверждение прямо из уведомления

```
As a пользователь,
I want нажать "Принял" прямо в уведомлении,
So that отметить приём не открывая приложение.

Acceptance Criteria:
Given показано уведомление с кнопками
When пользователь нажимает "✅ Принял"
Then уведомление убирается
Then приём фиксируется в истории со статусом "принято" и временем
Then счётчик таблеток уменьшается на 1 (если настроен)

Given пользователь нажимает "⏰ Снуз"
Then уведомление убирается
Then через 10 минут (или настроенный период) уведомление появляется снова
Then в истории фиксируется "отложен в [время]"

Given пользователь нажимает "✗ Пропустить"
Then уведомление убирается
Then в истории фиксируется "пропущено" со временем

Given пользователь нажимает на само уведомление (не на кнопки)
Then открывается приложение с экраном подтверждения
```

---

### Epic 5: История приёмов

#### US-09: Просмотр истории

```
As a пользователь,
I want видеть историю приёмов,
So that отслеживать соблюдение режима.

Acceptance Criteria:
Given пользователь открыл историю
When выбирает лекарство и период "последние 7 дней"
Then показывается список дат с иконками: ✅ принято, ❌ пропущено, 🔁 отложено
Then показывается процент соблюдения за период
```

---

### Epic 6: Пополнение запасов

#### US-10: Напоминание о пополнении

```
As a пользователь,
I want получать уведомление когда таблеток мало,
So that успеть купить лекарство заранее.

Acceptance Criteria:
Given установлен порог напоминания 5 таблеток
When остаток достигает 5
Then показывается уведомление "Осталось 5 таблеток [название]. Время пополнить запас."

Given пользователь вручную обновил количество на 30
When открывает карточку лекарства
Then счётчик показывает 30
```

## Data Model

```kotlin
// Лекарство
data class Medication(
    val id: Long,
    val name: String,           // "Метформин"
    val dose: String?,          // "500 мг"
    val colorIndex: Int,        // 0-9 (цвет иконки)
    val stockCount: Int?,       // остаток таблеток
    val stockThreshold: Int?,   // порог напоминания
    val isActive: Boolean,      // пауза/активно
    val createdAt: Long         // timestamp
)

// Расписание
data class Schedule(
    val id: Long,
    val medicationId: Long,
    val timeHour: Int,          // 0-23
    val timeMinute: Int,        // 0-59
    val daysOfWeek: Set<Int>,   // 1=пн..7=вс (пустой = каждый день)
    val startDate: LocalDate?,
    val endDate: LocalDate?
)

// Событие приёма
data class MedicationLog(
    val id: Long,
    val medicationId: Long,
    val scheduleId: Long,
    val scheduledAt: Long,      // запланированное время (timestamp)
    val actionAt: Long?,        // время действия пользователя
    val status: LogStatus,      // TAKEN, MISSED, SNOOZED, SKIPPED
    val snoozeCount: Int        // сколько раз откладывал
)

enum class LogStatus { TAKEN, MISSED, SNOOZED, SKIPPED }
```
