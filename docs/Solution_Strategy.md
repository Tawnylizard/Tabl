# Solution Strategy — Tabl

## Problem Statement (SCQA)

- **Situation:** Люди с хроническими заболеваниями и временными курсами лечения принимают лекарства по расписанию. Существуют десятки приложений-напоминалок.
- **Complication:** Стандартные push-уведомления легко игнорируются. Лучшие решения стали платными (Medisafe) или перегружены ненужными функциями (MyTherapy). Пользователи не хотят трекеры здоровья — им нужен только надёжный будильник.
- **Question:** Как создать Android-приложение, которое гарантированно напоминает о таблетках, не отвлекает лишними функциями и остаётся бесплатным?
- **Answer:** Нативное Android-приложение с настойчивыми heads-up push-уведомлениями через WorkManager, без бэкенда, без трекеров, без регистрации.

---

## First Principles Analysis

**Что нужно пользователю на фундаментальном уровне?**

1. Устройство должно привлечь внимание в нужное время
2. Пользователь должен подтвердить, что принял таблетку
3. Система должна помнить расписание даже после перезагрузки

**Что НЕ нужно:**
- Интернет
- Аккаунт
- Сервер
- Трекеры давления / сахара / веса
- Социальные функции

**Минимально необходимые компоненты:**
```
Лекарство (название, доза, расписание)
    + WorkManager (фоновое планирование)
    + NotificationCompat PRIORITY_HIGH (heads-up)
    + Room DB (история + настройки)
    = Работающий продукт
```

---

## Root Cause Analysis (5 Whys)

**Проблема:** Люди пропускают приём лекарств

1. **Почему?** → Забыли в нужный момент
2. **Почему забыли?** → Уведомление не привлекло достаточно внимания
3. **Почему не привлекло?** → Смахнули машинально, занятые другим
4. **Почему смахнули?** → Уведомление не требует осознанного действия
5. **Корневая причина:** Обычное уведомление не создаёт трение, достаточное для запоминания

**Решение корневой причины:**
> Будильник должен требовать **осознанного действия** (нажать "Принял") и **не давать уклониться** (нет быстрого закрытия без снуза).

---

## Game Theory Analysis

**Игроки:**
- Пользователь: хочет здоровье, не хочет тратить время
- Приложение: должно "победить" в конкуренции за внимание с другими уведомлениями
- Конкуренты: Medisafe (платный), Pillo (бесплатный, малоизвестный)

**Оптимальная стратегия (Nash Equilibrium):**
- Tabl не конкурирует функциями — конкурирует надёжностью и простотой
- Бесплатность → нет барьера установки
- Отсутствие трекеров → нет причины удалить ("зачем мне это?")
- Настойчивый будильник → высокая retention (реально помогает)

---

## Second-Order Effects

**Позитивные:**
- Реальная приверженность лечению → улучшение здоровья пользователей
- Сарафанное радио от пациентов и врачей
- Потенциал open-source сообщества

**Риски:**
- Агрессивный будильник может раздражать → решение: настраиваемая громкость и снуз
- Android ограничивает фоновые задачи → требует разрешения на точные будильники
- Обновления Android могут сломать AlarmManager поведение → нужны E2E тесты

---

## Contradictions Resolved (TRIZ)

| Противоречие | Тип | TRIZ принцип | Решение |
|-------------|-----|-------------|---------|
| Уведомление должно быть заметным И не раздражать | Физическое | Разделение во времени | Сначала heads-up с высоким приоритетом, повтор через 30 мин; снуз доступен |
| Приложение должно быть простым И функциональным | Техническое | Сегментация (принцип 1) | Простой главный экран + расширенные настройки скрыты |
| Будильник должен срабатывать точно И не разряжать батарею | Техническое | Использование ресурсов | AlarmManager.setExactAndAllowWhileIdle только для ближайшего будильника; WorkManager для планирования |
| Нет регистрации (приватность) И нужна история | Физическое | Разделение по условию | История хранится локально в Room DB — никуда не отправляется |

## Recommended Approach

### Архитектура решения

```
[Room DB] ←→ [Repository] ←→ [ViewModel]
                                    ↕
                              [Compose UI]
                                    ↕
                        [NotificationScheduler]
                                    ↕
                             [WorkManager]
                                    ↕
              [MedicationReminderWorker → NotificationManager]
                                    ↕
                      [NotificationActionReceiver]
```

### MVP Scope (приоритеты)

**Must Have (v1.0):**
1. Добавление / редактирование / удаление лекарства
2. Настройка расписания (время, дни недели, интервал)
3. Настойчивый будильник (AlarmManager + FLAG_INSISTENT)
4. Полноэкранный экран подтверждения (поверх локскрина)
5. Кнопки: "Принял" / "Снуз" / "Пропустить"
6. История приёмов (принято / пропущено / отложено)
7. Напоминание о пополнении запасов (счётчик таблеток)

**Nice to Have (v1.1+):**
- Экспорт истории в CSV
- Виджет на рабочий стол
- Тёмная тема

**Out of Scope:**
- Трекеры здоровья
- Синхронизация с облаком
- Функция опекуна
- iOS версия

### Risk Assessment

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Android убивает фоновый процесс | Высокая | Критичное | AlarmManager + REQUEST_IGNORE_BATTERY_OPTIMIZATIONS |
| Пользователь не даёт разрешение на точные будильники (API 31+) | Средняя | Высокое | Onboarding с объяснением + fallback |
| Конкурент Pillo улучшится | Низкая | Среднее | Фокус на простоте UX |
| Обновление Android ломает AlarmManager | Низкая | Критичное | CI тесты на эмуляторах разных версий API |
