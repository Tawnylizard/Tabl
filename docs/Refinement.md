## Edge Cases Matrix

| Сценарий | Вход | Ожидаемое поведение | Обработка |
|----------|------|---------------------|-----------|
| Два будильника одновременно | 2 лекарства в 09:00 | Показать оба последовательно | Очередь AlarmActivity, второй ждёт |
| Устройство в режиме Doze | Будильник во время Doze | Срабатывает точно через setExactAndAllowWhileIdle | AlarmManager.setExactAndAllowWhileIdle |
| Нет разрешения SCHEDULE_EXACT_ALARM (API 31+) | Первый запуск на Android 12+ | Экран onboarding с объяснением | Запрос через ACTION_REQUEST_SCHEDULE_EXACT_ALARM |
| Телефон выключен в момент будильника | Время прошло | Будильник пропущен, фиксируется как MISSED при следующем включении | BootReceiver сравнивает pending с текущим временем |
| Удаление лекарства во время активного снуза | Snooze timer активен | Снуз отменяется, лог обновляется | onDelete CASCADE в Room + cancelAlarm() |
| Изменение системного времени пользователем | Время переведено назад | Будильники пересчитываются | Слушаем ACTION_TIME_CHANGED broadcast |
| Очень длинное название лекарства (200+ символов) | "Ацетилсалициловая кислота форте плюс..." | Обрезается с "..." в UI | Ограничение 100 символов в поле ввода |
| Нулевой остаток таблеток | stockCount = 0 | Показывает "0 осталось" красным | Не блокирует будильник |
| Отключение уведомлений в системных настройках | Пользователь отозвал permission | Показ in-app баннера с просьбой включить уведомления | Проверка при каждом открытии приложения |
| MIUI/OneUI убивает фоновый процесс | Xiaomi/Samsung агрессивное управление батареей | Onboarding с инструкцией по настройке | Ссылка на dontkillmyapp.com по производителю |

## Testing Strategy

### Unit Tests (>80% coverage)

**Цели:**
- `AlarmScheduler` — вычисление следующего времени
- `MedicationRepository` — CRUD операции
- `HistoryViewModel` — расчёт процента соблюдения
- `calculateNextTrigger()` — граничные случаи расписания

### Integration Tests

**Цели:**
- Room DB миграции
- AlarmReceiver → AlarmService поток
- BootReceiver восстановление будильников

### E2E Tests (Espresso)

**Критические user journeys:**
1. Добавление лекарства → появляется в списке
2. Срабатывание будильника → нажать "Принял" → запись в истории
3. Перезагрузка → будильники восстановлены

## Test Cases (BDD)

### Feature: Будильник

```gherkin
Scenario: Happy path — пользователь подтверждает приём
  Given добавлено лекарство "Аспирин" с приёмом в 09:00 каждый день
  When наступает 09:00
  Then появляется heads-up push-уведомление с именем "Аспирин"
  And уведомление содержит кнопки "Принял", "Снуз", "Пропустить"

  When пользователь нажимает "Принял"
  Then уведомление убирается
  And в истории появляется запись "Принято" с временем ≈ 09:00

Scenario: Снуз — пользователь откладывает
  Given срабатывает будильник для "Аспирин"
  When пользователь нажимает "Снуз 10 мин"
  Then звук останавливается
  And через 10 минут будильник срабатывает снова

Scenario: Авто-пропуск — пользователь не отреагировал
  Given срабатывает будильник для "Аспирин"
  When пользователь не реагирует 60 минут
  Then статус меняется на "Пропущено"
  And показывается обычное (не настойчивое) уведомление

Scenario: Лимит снузов исчерпан
  Given установлен лимит снузов = 2
  And пользователь уже откладывал 2 раза
  When нажимает "Снуз" в третий раз
  Then кнопка "Снуз" недоступна
  And доступны только "Принял" и "Пропустить"
```

### Feature: Расписание

```gherkin
Scenario: Будильник только по будням
  Given лекарство с расписанием пн-пт в 08:00
  When наступает суббота 08:00
  Then будильник не срабатывает

  When наступает понедельник 08:00
  Then будильник срабатывает

Scenario: Курс завершён
  Given лекарство с курсом по 2026-04-20
  When наступает 2026-04-21
  Then будильник не срабатывает
  And лекарство помечается как "Курс завершён"
```

### Feature: Восстановление после перезагрузки

```gherkin
Scenario: Будильники восстанавливаются
  Given настроены будильники для 3 лекарств
  When пользователь перезагружает телефон
  Then приложение получает BOOT_COMPLETED
  And все 3 будильника перерегистрированы в AlarmManager
  And ни один не потерян
```

## Performance Optimizations

- Room запросы истории: индекс по `(medication_id, scheduled_at)` — запросы O(log n)
- Список лекарств: Flow из Room → только реактивные обновления, нет polling
- AlarmActivity: создаётся только при срабатывании, не держится в памяти
- Compose: `remember` и `derivedStateOf` для предотвращения лишних рекомпозиций

## Security Hardening

- Все `PendingIntent` с `FLAG_IMMUTABLE` (требование API 31+)
- `NotificationActionReceiver`: `android:exported="false"` в AndroidManifest
- PendingIntent requestCode = scheduleId (уникален, нет collision)
- Нет WebView, нет произвольного исполнения кода
- ProGuard/R8 минификация в release build

## Accessibility (a11y)

- Минимальный размер кнопок: 56dp (WCAG)
- Контраст текста ≥ 4.5:1 (WCAG AA)
- ContentDescription на всех иконках
- Кнопки на экране будильника — крупные, простые (без мелких элементов)
- Поддержка TalkBack
