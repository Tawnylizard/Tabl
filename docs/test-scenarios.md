## Feature: Управление лекарствами

### US-01: Добавление лекарства

```gherkin
Feature: Добавление лекарства

  Background:
    Given пользователь находится на главном экране
    And список лекарств пуст

  # Happy Path
  Scenario: Успешное добавление лекарства с названием
    When пользователь нажимает "Добавить лекарство"
    And вводит название "Метформин"
    And нажимает "Сохранить"
    Then лекарство "Метформин" отображается в списке
    And уведомления для него активны

  Scenario: Добавление лекарства с полными данными
    When пользователь добавляет лекарство с:
      | Поле           | Значение      |
      | Название       | Аспирин       |
      | Доза           | 100 мг        |
      | Запас          | 30            |
      | Порог          | 5             |
      | Цвет           | Синий (idx=2) |
    And нажимает "Сохранить"
    Then карточка "Аспирин" показывает дозу "100 мг"
    And счётчик запаса показывает "30"

  # Error Handling
  Scenario: Попытка сохранить без названия
    When пользователь нажимает "Сохранить" с пустым полем названия
    Then показывается ошибка "Введите название лекарства"
    And экран добавления не закрывается

  Scenario: Название из одних пробелов
    When пользователь вводит "   " в поле названия
    And нажимает "Сохранить"
    Then показывается ошибка "Введите название лекарства"

  # Edge Cases
  Scenario: Название максимальной длины
    When пользователь вводит название длиной 100 символов
    And нажимает "Сохранить"
    Then лекарство сохраняется успешно
    And название обрезается или помещается полностью в карточке

  Scenario: Добавление дубликата названия
    Given уже существует лекарство "Метформин"
    When пользователь добавляет ещё одно "Метформин"
    Then оба лекарства сохраняются (дубликаты разрешены)
```

### US-02: Редактирование лекарства

```gherkin
Feature: Редактирование лекарства

  Background:
    Given существует лекарство "Метформин" с приёмом в 09:00 и 21:00
    And история содержит 5 записей TAKEN

  # Happy Path
  Scenario: Изменение времени приёма
    When пользователь открывает редактирование "Метформин"
    And меняет время с 09:00 на 10:00
    And сохраняет
    Then следующий будильник запланирован на 10:00
    And 5 записей в истории остаются неизменными

  # Error Handling
  Scenario: Сохранение без названия при редактировании
    When пользователь очищает название лекарства
    And нажимает "Сохранить"
    Then показывается ошибка "Введите название лекарства"
    And предыдущее название не изменено

  # Edge Cases
  Scenario: Редактирование при активном уведомлении
    Given для "Метформин" показано активное уведомление
    When пользователь редактирует время с 09:00 на 10:00 и сохраняет
    Then активное уведомление не затронуто
    And следующий будильник в 10:00 запланирован корректно

  Scenario: Пауза лекарства (isActive = false)
    When пользователь переключает "Метформин" в режим паузы
    Then все будущие будильники отменяются
    And лекарство остаётся в списке с пометкой "Пауза"
    And история не изменяется
```

### US-03: Удаление лекарства

```gherkin
Feature: Удаление лекарства

  Background:
    Given существует лекарство "Ибупрофен" с расписанием на 12:00

  # Happy Path
  Scenario: Подтверждение удаления
    When пользователь нажимает "Удалить" для "Ибупрофен"
    And подтверждает диалог "Удалить?"
    Then "Ибупрофен" исчезает из списка
    And все запланированные будильники для него отменены
    And AlarmManager не вызывает тревогу в 12:00

  # Error Handling
  Scenario: Отмена удаления
    When пользователь нажимает "Удалить" для "Ибупрофен"
    And нажимает "Отмена" в диалоге
    Then "Ибупрофен" остаётся в списке
    And все будильники сохранены

  # Edge Cases
  Scenario: Удаление лекарства с активным уведомлением
    Given для "Ибупрофен" отображается активное уведомление
    When пользователь удаляет лекарство
    Then уведомление убирается из шторки
    And лекарство удалено из Room DB
```

## Feature: Расписание приёма

### US-04: Настройка времени приёма

```gherkin
Feature: Расписание приёма

  # Happy Path
  Scenario: Расписание по дням недели
    Given пользователь настраивает расписание для "Витамин D"
    When выбирает дни "пн, ср, пт" и время 09:00
    Then будильник срабатывает только в понедельник, среду, пятницу в 09:00
    And в субботу и воскресенье будильника нет

  Scenario: Ежедневное расписание
    When пользователь выбирает "каждый день" и время 21:00
    Then будильник срабатывает ежедневно в 21:00

  Scenario: Интервальное расписание (каждые 8 часов)
    When пользователь устанавливает интервал "каждые 8 часов" с 08:00
    Then будильники срабатывают в 08:00, 16:00, 00:00

  # Error Handling
  Scenario: Добавление расписания без выбора дней
    When пользователь не выбирает дни недели и сохраняет
    Then показывается ошибка "Выберите хотя бы один день"

  # Edge Cases
  Scenario: Несколько временных слотов для одного лекарства
    When пользователь добавляет второй слот 21:00 к уже существующему 09:00
    Then оба будильника срабатывают независимо
    And каждый создаёт отдельную запись в истории
```

### US-05: Курс приёма

```gherkin
Feature: Курс приёма

  # Happy Path
  Scenario: Автоматическое завершение курса
    Given пользователь установил курс "Антибиотик" с 2026-04-16 по 2026-04-23
    When наступает 2026-04-24 00:00
    Then будильники для "Антибиотик" больше не срабатывают
    Then в истории отображается статус "Курс завершён"

  Scenario: Будильники активны в последний день курса
    Given курс "Антибиотик" заканчивается 2026-04-23
    When наступает 2026-04-23 09:00 (время приёма)
    Then будильник срабатывает

  # Error Handling
  Scenario: Дата окончания раньше даты начала
    When пользователь устанавливает startDate = 2026-04-20, endDate = 2026-04-18
    Then показывается ошибка "Дата окончания должна быть позже даты начала"

  Scenario: Дата окончания в прошлом при создании
    When пользователь устанавливает endDate в прошлом
    Then показывается предупреждение "Курс уже завершён"
    And пользователю предлагается изменить дату

  # Edge Cases
  Scenario: Бессрочный приём (endDate не задан)
    Given лекарство создано без endDate
    When проходит 365 дней
    Then будильники продолжают срабатывать
```

## Feature: Push-уведомления

### US-06: Срабатывание push-уведомления

```gherkin
Feature: Push-уведомления

  # Happy Path
  Scenario: Heads-up уведомление в назначенное время
    Given лекарство "Метформин" 500 мг с расписанием в 09:00
    When наступает 09:00
    Then появляется heads-up уведомление
    And уведомление содержит: "Метформин", "500 мг", время "09:00"
    And уведомление содержит кнопки "Принял", "Снуз", "Пропустить"

  Scenario: Уведомление при заблокированном экране
    Given телефон заблокирован
    When наступает время приёма
    Then уведомление отображается поверх локскрина (heads-up)

  # Error Handling
  Scenario: Повтор через 30 минут при отсутствии реакции
    Given уведомление показано в 09:00
    When пользователь не реагирует 30 минут
    Then в 09:30 появляется повторное уведомление
    And snoozeCount для записи лога = 1

  Scenario: Финальный статус MISSED после 2 повторов
    Given уведомление повторилось дважды без ответа (в 09:00, 09:30, 10:00)
    When истекают ещё 30 минут без ответа
    Then запись в MedicationLog получает статус MISSED
    And уведомление убирается из шторки автоматически

  # Edge Cases
  Scenario: Уведомление в Doze Mode
    Given Android Doze Mode активен
    When наступает время приёма
    Then AlarmManager с setExactAndAllowWhileIdle() обеспечивает срабатывание
    And отклонение от запланированного времени ≤ 1 минуты

  Scenario: Точность срабатывания — NFR
    Given запланированное время 09:00:00
    When AlarmManager срабатывает
    Then фактическое время срабатывания в диапазоне 09:00:00 – 09:01:00
```

### US-07: Устойчивость к перезагрузке

```gherkin
Feature: Устойчивость к перезагрузке

  # Happy Path
  Scenario: Восстановление будильников после перезагрузки
    Given настроены будильники для лекарств: "Метформин" (09:00), "Аспирин" (12:00), "Витамин" (21:00)
    When пользователь перезагружает телефон
    Then приложение получает BOOT_COMPLETED broadcast
    And все 3 будильника восстановлены в AlarmManager
    And восстановление завершено в течение 30 секунд после BOOT_COMPLETED

  Scenario: Будущие будильники не пропускаются
    Given следующий будильник запланирован через 2 часа
    When телефон перезагружается и восстанавливается
    Then будильник срабатывает в запланированное время (±1 минута)

  # Error Handling
  Scenario: Будильник пропущен во время перезагрузки
    Given будильник был запланирован на 09:00
    And перезагрузка началась в 08:58 и завершилась в 09:03
    When телефон загружается
    Then пропущенный будильник фиксируется как MISSED в истории
    And новый будильник для следующего дня запланирован корректно

  # Edge Cases
  Scenario: Множественные перезагрузки подряд
    When телефон перезагружается 3 раза подряд в течение 5 минут
    Then будильники восстанавливаются корректно без дубликатов
    And в AlarmManager нет задвоенных тревог

  Scenario: Приложение удалено и переустановлено
    Given данные Room DB очищены при переустановке
    When приложение запускается впервые после переустановки
    Then список лекарств пуст
    And никаких зависших будильников нет
```

## Feature: Подтверждение приёма

### US-08: Подтверждение прямо из уведомления

```gherkin
Feature: Подтверждение приёма из уведомления

  Background:
    Given активно уведомление для "Метформин 500 мг" в 09:00

  # Happy Path — Принял
  Scenario: Подтверждение приёма кнопкой "Принял"
    When пользователь нажимает "✅ Принял" в уведомлении
    Then уведомление убирается немедленно
    And в MedicationLog создаётся запись: статус TAKEN, actionAt = текущее время
    And счётчик запаса уменьшается на 1 (если stockCount > 0)

  # Happy Path — Снуз
  Scenario: Откладывание приёма кнопкой "Снуз"
    When пользователь нажимает "⏰ Снуз" в уведомлении
    Then уведомление убирается немедленно
    And через 10 минут (дефолтный период) появляется новое уведомление
    And в MedicationLog создаётся запись: статус SNOOZED, время = текущее

  Scenario: Снуз с кастомным периодом 30 минут
    Given в настройках установлен снуз 30 минут
    When пользователь нажимает "⏰ Снуз"
    Then следующее уведомление появляется ровно через 30 минут

  # Happy Path — Пропустить
  Scenario: Намеренный пропуск кнопкой "Пропустить"
    When пользователь нажимает "✗ Пропустить"
    Then уведомление убирается немедленно
    And в MedicationLog создаётся запись: статус SKIPPED, actionAt = текущее время
    And счётчик запаса НЕ уменьшается

  # Happy Path — Тап на уведомление
  Scenario: Открытие приложения тапом на уведомление
    When пользователь нажимает на тело уведомления (не на кнопки)
    Then открывается приложение
    And открывается экран подтверждения с деталями "Метформин 500 мг"

  # Edge Cases
  Scenario: Нажатие кнопки при нулевом запасе
    Given stockCount = 0
    When пользователь нажимает "✅ Принял"
    Then приём фиксируется как TAKEN
    And stockCount остаётся 0 (не уходит в отрицательное)
    And показывается уведомление "Запас закончился"

  Scenario: Несколько одновременных уведомлений (2 лекарства в одно время)
    Given два лекарства "А" и "Б" с приёмом в 09:00
    When наступает 09:00
    Then оба уведомления показаны независимо
    And "Принял" для "А" не влияет на уведомление "Б"
```

## Feature: История приёмов

### US-09: Просмотр истории

```gherkin
Feature: История приёмов

  Background:
    Given существует лекарство "Метформин"
    And за последние 7 дней: 10 TAKEN, 2 MISSED, 1 SNOOZED, 1 SKIPPED

  # Happy Path
  Scenario: Просмотр истории за 7 дней
    When пользователь открывает историю
    And выбирает лекарство "Метформин" и период "7 дней"
    Then показывается список дат с иконками:
      | TAKEN   | ✅ |
      | MISSED  | ❌ |
      | SNOOZED | 🔁 |
      | SKIPPED | ✗  |

  Scenario: Расчёт процента соблюдения
    Given за 7 дней: 10 TAKEN, 2 MISSED, 0 SNOOZED, 1 SKIPPED
    When пользователь просматривает статистику
    Then процент соблюдения = 10 / (10 + 2 + 1) × 100 = 77%
    And SNOOZED не учитывается в знаменателе

  Scenario: Просмотр за 30 дней
    When пользователь выбирает период "30 дней"
    Then показывается статистика за 30 дней
    And процент рассчитан по тем же правилам

  # Error Handling
  Scenario: Пустая история (новое лекарство)
    Given лекарство добавлено 5 минут назад
    When пользователь открывает историю
    Then показывается сообщение "История приёмов пуста"

  # Edge Cases
  Scenario: История при 100% соблюдении
    Given за 7 дней: 14 TAKEN, 0 MISSED, 0 SKIPPED
    Then процент соблюдения = 100%
    And экран показывает положительный индикатор

  Scenario: Фильтрация по нескольким лекарствам
    When пользователь не выбирает конкретное лекарство
    Then показывается сводная история для всех лекарств
```

## Feature: Пополнение запасов

### US-10: Напоминание о пополнении

```gherkin
Feature: Напоминание о пополнении запасов

  Background:
    Given лекарство "Метформин" с порогом напоминания 5 таблеток

  # Happy Path
  Scenario: Уведомление при достижении порога
    Given stockCount = 6
    When пользователь нажимает "Принял" (stockCount становится 5)
    Then появляется уведомление "Осталось 5 таблеток Метформин. Время пополнить запас."

  Scenario: Ручное обновление запаса
    When пользователь открывает карточку "Метформин"
    And обновляет количество на 30
    Then счётчик на карточке показывает 30
    And уведомление о пополнении не отображается

  # Error Handling
  Scenario: Запас достигает 0
    Given stockCount = 1
    When пользователь нажимает "Принял"
    Then stockCount = 0
    Then показывается уведомление "Таблетки закончились. Пополните запас."
    And stockCount не уходит в отрицательное значение

  Scenario: Ввод отрицательного количества при ручном обновлении
    When пользователь вводит "-5" в поле количества
    Then показывается ошибка "Введите положительное число"

  # Edge Cases
  Scenario: Порог не задан — уведомлений нет
    Given для лекарства stockThreshold = null
    When stockCount достигает 2
    Then уведомление о пополнении НЕ показывается

  Scenario: Уведомление о пополнении не дублируется
    Given stockCount = 5 (на пороге)
    When пользователь нажимает "Принял" ещё раз (stockCount = 4)
    Then повторное уведомление НЕ показывается (одно уведомление на "ниже порога")
```

## Feature: NFR — Производительность и автономность

```gherkin
Feature: Non-Functional Requirements

  Scenario: Холодный старт приложения
    Given приложение не запущено (процесс убит)
    When пользователь открывает приложение
    Then главный экран отображается в течение 2 секунд

  Scenario: Размер APK
    When собирается release APK
    Then размер файла ≤ 15 МБ

  Scenario: Полная автономность — нет сетевых запросов
    Given отключён WiFi и мобильный интернет
    When пользователь выполняет любое действие в приложении
    Then все функции работают корректно без ошибок
    And в логах нет попыток сетевых запросов

  Scenario: WCAG AA контраст
    Given светлая тема
    When элементы интерфейса отображаются
    Then контрастность текст/фон ≥ 4.5:1 (WCAG AA)
    And минимальный размер шрифта ≥ 14sp
```
